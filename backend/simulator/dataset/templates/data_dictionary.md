# Dataset Data Dictionary

This file documents the tables generated by `python -m backend.simulator.dataset.generate`
(PR164). It is copied verbatim into every generated dataset directory —
see `dataset_manifest.json` in this same directory for the specific
dataset's identity, generation command, and file hashes.

---

## Supported and unsupported fault classes

**Supported in this dataset version:**

- `normal_operation` — healthy operation, no fault.
- `cooling_degradation` — reduced cooling-subsystem effectiveness (physical fault).
- `hydrogen_supply_issue` — reduced fuel-supply factor (physical fault, includes
  the PR162 voltage-droop correction).
- `sensor_anomaly` — a linear-ramp temperature *sensor* bias (telemetry-layer
  corruption, not a physical fault — see `fault_type` vs. `sensor_corruption_type`
  below).

**Not supported** (do not assume present, even if a value superficially
resembles one): membrane dehydration, any combined/simultaneous fault,
sensor dropout, sensor delay, stuck-at sensor behavior, sensor drift beyond
the existing linear bias ramp, and hydrogen pressure dynamics beyond what
the base simulator already models.

---

## `telemetry.parquet`

One row per emitted observation. This is **observable telemetry** — the
same core+derived values (see PR163's raw/derived consistency correction)
that a real inference system would see, including sensor noise where
configured. It is never the clean, hidden simulator state.

| Column | Type | Null? | Description |
|---|---|---|---|
| `dataset_id` | string | no | Identifies the dataset this row belongs to. |
| `simulation_run_id` | string | no | Foreign key into `runs.parquet`. |
| `observation_id` | string | no | Globally unique per observation; useful for dedup checks. |
| `timestamp` | timestamp (UTC, µs) | no | `run_start_time + elapsed_sim_seconds`. Never wall-clock. |
| `elapsed_sim_seconds` | float64 | no | Simulated seconds since this run started. |
| `asset_id` | string | no | Which Plant Alpha stack this observation is for. |
| `measurement_type` | string | no | One of the core (`stack_temperature`, `stack_pressure`, `current`, `voltage`, `fuel_flow`) or derived (`power_output`, `efficiency`, `coolant_flow`) channels. |
| `value` | float64 | no | The measurement value, in `unit`. Noisy where sensor noise is configured for that channel; derived values are recomputed from the noisy core values they depend on (see PR163 correction) — never silently clean. |
| `unit` | string | no | Physical unit of `value` (°C, kPa, A, V, SLPM, kW, percent, L/min). |

## `ground_truth.parquet`

One row per asset per sample time. Ground truth is **always clean** —
computed only from the run's configuration and elapsed simulated time,
never from telemetry values and never affected by sensor noise.

| Column | Type | Null? | Description |
|---|---|---|---|
| `dataset_id` | string | no | |
| `simulation_run_id` | string | no | Foreign key into `runs.parquet`. |
| `timestamp` | timestamp (UTC, µs) | no | Same clock as `telemetry.parquet`. |
| `elapsed_sim_seconds` | float64 | no | |
| `asset_id` | string | no | |
| `fault_type` | string | no | The run's configured **physical** fault (`none`, `cooling_degradation`, `hydrogen_supply_issue`) — constant for the whole run on the target asset; `none` on every other asset. Distinct from `fault_active`: a sample can have a non-`none` `fault_type` while `fault_active` is `false`, before or after the fault window. |
| `fault_active` | bool | no | Whether elapsed time is within `[fault_start, fault_end)` for this asset. |
| `fault_severity` | float64 | no | Instantaneous, ramped effective severity in `[0, 1]` — `0.0` when inactive, ramping from `0.0` toward the run's configured maximum while active. Never means "remaining health." |
| `seconds_since_fault_start` | float64 | **yes** | Null exactly when `fault_active` is `false` — never a sentinel like `-1`. |
| `sensor_corruption_type` | string | no | The run's configured **telemetry-layer** corruption (`none` or `bias`) — separate from `fault_type` because `sensor_anomaly` corrupts a sensor reading, not the plant. |

## `runs.parquet`

One row per planned run: its fully resolved configuration plus its
execution outcome.

| Column | Type | Null? | Description |
|---|---|---|---|
| `dataset_id` | string | no | |
| `simulation_run_id` | string | no | Primary key. Deterministic: `{dataset_id}-{class_label}-{index:04d}`. |
| `class_label` | string | no | The scenario this run represents — same vocabulary as `fault_type`/`fault_corruption_type` scenario names. |
| `seed` | int64 | no | The seed that resolved this run's operating conditions and sensor-noise draws. |
| `target_asset_id` | string | no | The one asset a fault (if any) was injected on. |
| `duration_sim_seconds` | float64 | no | |
| `dt_seconds` | float64 | no | Sample interval. |
| `run_start_time` | timestamp (UTC, µs) | no | The spec-declared anchor for this run's telemetry timestamps. |
| `fault_start_sim_seconds` | float64 | **yes** | Null exactly for a `normal_operation` run. |
| `fault_duration_sim_seconds` | float64 | **yes** | Null exactly for a `normal_operation` run. |
| `fault_severity` | float64 | no | The run's *configured maximum* severity (`0.0` for healthy runs; fault runs require `>0.0`). |
| `load_baseline_percent` / `load_amplitude_percent` / `load_period_seconds` / `load_phase_radians` | float64 | no | Resolved (not range) load-oscillation profile — see PR163. |
| `initial_load_offset_percent` / `initial_stack_temperature_offset_celsius` | float64 | no | Resolved initial-state offsets for `target_asset_id`. |
| `sensor_noise_json` | string | no | Stable JSON array of `{measurement_name, standard_deviation, clip_std_multiple}` — the one genuinely nested piece of configuration. |
| `observation_count` | int64 | no | Rows this run contributed to `telemetry.parquet`. |
| `ground_truth_row_count` | int64 | no | Rows this run contributed to `ground_truth.parquet`. |
| `sample_count` | int64 | no | Number of simulated ticks sampled. |
| `status` | string | no | `"success"` for every row in this file — a failed run aborts generation entirely (see below) rather than being recorded as a failed row. |
| `error_message` | string | **yes** | Always null in this dataset version. |

## Timestamp semantics

Every timestamp in every table is `run_start_time + elapsed_sim_seconds`,
timezone-aware UTC, derived from the spec's declared `run_start_time` —
never `datetime.now()`. Two rows with the same `(simulation_run_id,
elapsed_sim_seconds)` always have the same `timestamp`.

## Severity semantics

`0.0` = no fault effect (only valid for `normal_operation`); `1.0` = the
maximum effect the run was configured for. `fault_severity` in
`ground_truth.parquet` is the *instantaneous* value at that sample;
`fault_severity` in `runs.parquet` is the run's *configured maximum*.

## Run-level split policy

`splits.json` assigns whole runs — never individual rows — to
train/validation/test, stratified by `(class_label, target_asset_id)` and
deterministically shuffled per dataset. No run ID appears in more than one
split. See `dataset_manifest.json`'s `split_counts` for this dataset's
totals.

## Synthetic-data limitations

This is a lumped-parameter simulator, not a full electrochemical /
thermal-fluid model — see `docs/simulator.md` and the ODIS v1.1 repository
audit for what physics each fault class does and does not represent.
Treat class boundaries, severity magnitudes, and noise levels as
illustrative for a first baseline, not as calibrated to any specific real
PEM stack.
